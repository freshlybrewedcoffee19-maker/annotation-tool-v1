## Machine and method

- Windows laptop, Intel Core Ultra 5 225H, Intel Arc 130T integrated graphics, 15.43 GiB physical RAM, browser reports 14 logical processors.
- Installed Chrome and Edge 154, automated headless sessions. WebGPU selected Intel `xe-lpg`, not a fallback adapter. This is one laptop, not a low-end compatibility matrix or a visible-browser battery test.
- ONNX Runtime Web 1.24.3. Single-thread WebAssembly CPU and WebGPU were requested separately. Successful WebGPU sessions do not prove every graph operation stayed on the GPU.
- Video source: existing 45-second Convex trial, 848 × 478, 1,829,761 bytes. Successfully fetched in an isolated trial workspace into a browser Blob, decoded and read via canvas. No workspace keys are recorded in benchmark artifacts.
- Processing frame size 640 × 360; BGR float32 crops, template 127 × 127, search 255 × 255. Fifty frames sampled at five per second from trial times 2.2–12.0 seconds, initialized at 2.0 seconds.
- Models run in a browser worker. Frames are requested one at a time; no whole-video pixel array. No remote inference requests: recorded requests during tracking were local benchmark files only.
- Five controlled sequences use a hand-selected shirt crop from the trial: motion, complete disappearance/reappearance, partial occlusion, a lookalike crossing, and a scene change. Each has 50 measured inference frames. Controlled reference positions and visibility are explicitly generated by the fixture. They are not independent real-world footage.
- Real-trial reference boxes were selected by hand at six inspected times; the five later boxes are scored. The shirt barely moves in this interval. Uninspected frames are not labelled as measured accuracy ground truth.

## Model provenance and repair

Pinned upstream [NanoTrack](https://github.com/HonglinChu/SiamTrackers/tree/248663fde6bf7c40190cf10ee396d5662919ecd3/NanoTrack), Apache 2.0 notice retained in LICENSE. Source tracker, crop code, configuration and export script are retained for comparison. Exact weights and SHA-256 hashes are in manifest.json. Model files stay ignored by Git and out of public/ and production bundles.

Original backbone: 1,431,635 bytes. Head: 1,183,740 bytes. Original combined weights: 2,615,375 bytes (2.49 MiB). The original backbone actually rejects the required 127 × 127 template input: `Got: 127 Expected: 255` on both spatial dimensions. Merely loading the model would have missed this failure.

prepare.py makes a second backbone with declared input 127 × 127 and output 8 × 8. It changes no weights or operators. This derived file is 1,431,633 bytes, bringing the experiment's three model files to 4,047,008 bytes (3.86 MiB). ONNX validation and actual template/backbone/head inference passed on both browser paths. This repair is a developer preparation step; browser users would not install Python.

The JavaScript adapter ports the pinned V3 tracker parameters and postprocessing. Canvas crop resizing is not guaranteed bit-identical to upstream OpenCV. Browser CPU/GPU outputs agree closely in this experiment, but upstream numerical parity has not been established.

|---|---:|---:|---:|
| Chrome CPU | 1.10 s | 1.44 s | 27.60 ms |
| Chrome graphics | 1.38 s | 3.05 s | 59.79 ms |
| Edge CPU | 1.18 s | 1.42 s | 26.71 ms |
| Edge graphics | 1.50 s | 3.07 s | 60.52 ms |

All six sequences completed in each run. Each controlled 50-frame sequence took 1.32–1.51 s CPU and 2.37–2.63 s graphics. The proposed 30-second gate for ten seconds at five sampled frames per second passes **on this machine**. Initial shader compilation is included, not silently dropped.

The main page's 16 ms timer continued during worker processing; largest observed gaps were 24.9–27.0 ms. This supports basic responsiveness, not a complete measurement of the production editor under inference. Cancellation at frame request 5 terminated the worker and resolved in less than the timer's reporting precision (`0 ms`); it did not continue an accepted track. A deliberately missing template file returned `Missing template.onnx`. The existing manual app is untouched; no production fallback UI was integrated.

results.json contains separate loading/blank-input microbenchmarks. Cold model retrieval from **localhost**, including Cache Storage writes, took roughly 29–32 ms per file in Chrome; later Cache Storage reads were roughly 5–8 ms. Those are not internet-download results. Runtime files were also served locally. Real first-download time on a user's connection has not been measured. Inference-only blank-frame timings are not tracking accuracy measurements.

Full worker/GPU/process peak memory was **not measured**. A 640 × 360 RGBA frame is 921,600 bytes; search and template input arrays are 780,300 and 193,548 bytes. These are calculable buffer sizes, not a total memory estimate. Model buffers, runtime heaps, decoder memory and graphics allocations add overhead. This gate remains open.

## Accuracy and disappearance

Box overlap is intersection divided by union, where 1 means identical rectangles. The five hand-checked later trial frames scored 0.941–0.948 on both paths. This is a coarse static-shirt check, not a general accuracy percentage.

Controlled motion mean overlap was 0.942. The disappearance sequence contained 15 absent frames; **12 produced raw tracker scores at least 0.8 despite the object being absent**. The first absent frame had a low score and caused the diagnostic stop latch at frame 20. Continuing raw inference solely for evaluation showed why accepting later high scores or automatically reconnecting would be unsafe. No such raw result became an accepted box.

Partial occlusion never triggered the score-only stop. In the crossing-lookalike case, six frames overlapped the distractor more than the target; overlap during the crossing itself makes this a confusion indicator, not six independently confirmed identity-switch events. Mean target overlap dropped to 0.864. Scene change triggered a diagnostic stop at frame 20; none of its 31 absent frames exceeded the 0.8 threshold. Scores are heuristics, not presence probabilities.

Every experimental row is stored as **Needs checking**, with `acceptedBox: null`, including visible proposals. Raw model coordinates are diagnostic evidence only and are not drawn as accepted annotations. There is no accepted interpolation across disappearance, automatic identity merge or automatic resume. A future resume must ask the user to locate the reappearing object and confirm its box; a high score cannot answer that question.

## Tracking safety guard — 7 October 2026 (local only)

Added provisional appearance, geometry/motion and multiple-candidate checks to the pinned browser tracker. The reference appearance is frozen to the manually confirmed initial frame; it is not automatically replaced with whatever the tracker follows. Stops latch permanently for that run. Normal worker processing stops at the failing frame; diagnostic continuation must be explicitly requested and never yields accepted annotations. A resumed run rejects an unconfirmed reappearance box. All output remains Needs checking with acceptedBox null.

Provisional thresholds: raw response >=0.8, appearance histogram overlap >=0.85, area ratio 0.5–2, centre displacement <= half the previous longest side. Competing high-response regressed boxes with overlap <0.5 flag ambiguity. These thresholds were explored using this one trial and controlled fixtures; they are not calibrated probabilities or general object-presence guarantees. Identical objects and similar-colour backgrounds can still fool them.

`run-safety.mjs` validates all model hashes, exercises high-score missing appearance, invalid geometry, stop latching and explicit resume, then runs actual CPU inference. `safety-results.json` contains measured evidence, not a production accuracy claim. The controlled fixture uses generated target placement/absence, not real disappearance footage.

Final Chrome run: smooth motion kept all 50 proposals; disappearance and scene cut stopped at the first absent frame (index 20), with zero proposals during controlled absence. Partial occlusion stopped at its first covered frame (20). The lookalike case stopped for multiple plausible boxes at index 30, before the previous raw tracker’s clear jump at 45. Suppression after a stop, including after reappearance, is intentional until user confirmation. A confirmed synthetic reappearance at frame 35 resumed for 15 frames; an unconfirmed attempt failed. This does not establish real-world identity preservation.

The corrected real moving-iron clip processed all 50 samples in 3.37 seconds, with all 51 presentations checked and no safety stop. It remains a visually inspected motion example without independent frame-by-frame accuracy labels. No remote request occurred during inference; weights/runtime were served locally. Cancellation and missing-model checks passed separately. The local iron preview hides stopped proposals and reports actual processed counts. It saves no annotations.

Reproduce with the existing local benchmark server and `node benchmarks/nanotrack/run-safety.mjs`; model preparation requirements above still apply. Production UI/backend/model assets were not deployed. Remaining release gates: real disappearance/reappearance and lookalikes, total memory, cold internet download and weaker-laptop evidence. Do not enable assisted tracking from these fixture results alone.
